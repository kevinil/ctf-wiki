# CTF 知识字典 —— 设计文档

日期：2026-11-01
状态：待实现

---

## 1. 背景与意图

CTF 的教学资料是离散的：每个方向都有大量独立教程和 writeup，但缺少一层"**识别**"。

真实场景是：拿到一道题，附件一堆、题干只有一句话，人卡在第一步——**这算什么题？该查什么？先试什么？**

现有题库的问题不是题不够，是解释不成体系：同一类题散落在几十篇 writeup 里，没有一份东西告诉你"看到 X 特征，就该先做 Y"。

因此本项目的核心不是教程合集，而是**识别层 + 行动优先级**。

### 核心类比：魔兽世界输出循环

战斗输出不是"知道所有技能"，而是一张**优先级列表**：从最高优先级的技能开始，条件满足就打，条件不满足就滑到下一条，打完回到顶部重扫。

本项目的"输出循环"即：从成本最低、命中率最高的判断开始，命中就停下执行，不命中就滑到下一条；执行完再回到顶部重扫。

## 2. 目标

1. 覆盖六大方向（Web / Pwn / Reverse / Crypto / Misc / 取证），共约 **58 个题型页**。
2. 每个题型页有固定六段结构（见 §6）。
3. 首页提供一张"**看到什么特征 → 跳哪一页**"的总表，这是一眼认出题型的那一层。
4. 一个通用的"**开场起手**"与"**卡住怎么办**"元流程，适用于任何方向。
5. VitePress 静态站，中文，术语保留英文。
6. 构建后可在本地离线浏览（提供一键脚本）。

## 3. 非目标

- 不是从零教学的入门课程。假设读者会基本的 Linux 命令行、会读 Python、知道 `file` / `strings` 是什么。
- 不是在线判题平台，不做 flag 校验。
- 不整篇转载别人的 writeup。
- 不做用户系统、评论、后端、账号。

## 4. 反目标（即使技术上都跑通也算失败）

1. "判断流程"退化成知识点罗列，只有名词没有"做什么动作"。每一条必须能对应一个可执行动作。
2. 变成链接搬运站：正文大量是外链，本站自身没有可读内容。
3. 例题解析无法复现、或直接抄二手题解导致命令/结果对不上。
4. 题型页之间大量复制粘贴，同一段话出现在十几个页面里。
5. 站点为了好看牺牲检索：搜不到就等于没有。

## 6. 页面模板

每个题型页固定六段，顺序不变：

### ① 识别指纹

这题长什么样。列出可观察信号：

- 附件类型与后缀（`.pcap`、`.zip`、ELF 架构、`.apk`…）
- 题干关键词（"登录"、"内网"、"上传"、"注册码"…）
- 分值 / 通过率 / 出题人风格
- 本类题在比赛中的典型位置（如 crypto 第一题往往是古典密码）

### ② 考什么

知识点清单，每条一句话，不展开教学。展开教学不是本项目的职责。

### ③ 判断流程（核心）

纯 Markdown 有序列表。每条形如：

```
条件 → 动作 → 命中后停止 / 继续往下
```

写作规范：

- **按成本排序**：0 成本（看一眼文件名、`file`、`strings`）永远在最前。
- **命中即停**：一旦条件成立，执行动作后跳到指定条目或直接结束。
- **兜底**：每隔 3–4 条要有一条"以上都不成立 → 回到第 1 条，换一个粒度重看"，防止整条链走空。
- **禁止模糊词**："可能需要"、"或许可以"这类词不允许出现；必须是可判定的条件和可执行的动作。
- **可执行**：每条动作都要能在几分钟内做完，不能是"深入理解 XX 原理"。

示例（压缩包类）：

```markdown
1. `file` 看到 `Zip archive` → 直接进 2；不是 zip → 跳第 6 条
2. 解压成功且拿到明文 → 本链结束，看内容再分流
3. 解压报密码错误 → 先查伪加密（`010 Editor` 改 flag），不行跳 4
4. 文件名可见但 CRC 报错 → 试 CRC32 碰撞修复
5. 有同名明文文件 → 试明文攻击（bkcrack）
6. 以上都不成立 → 回到第 1 条，用 `binwalk -e` 从二进制视角重看
```

### ④ 工具与命令

可直接复制的命令块，带一行注释说明用途。每个命令标出常见参数陷阱。

### ⑤ 常见坑

"看起来是 A 其实是 B"的列法。每条格式：`现象 → 实际原因 → 正确应对`。

### ⑥ 一道例题

结构固定：

- **题目**：比赛、年份、题名、原始来源链接
- **题干**：原始描述
- **附件**：是什么
- **关键观察**：从哪里看出来的
- **走了哪条链**：明确写出命中判断流程的第几条
- **命令与输出**：真实跑过的
- **flag**

约束：只用公开经典原题；解析自己写并本地复现；不复述别人的 writeup 原文。

## 7. 通用元页面

- `meta/opening.md` —— 开场起手：任何题到手先做的 5 件事（读题干两遍 / 看附件类型 / 记下分值 / 看是否有 hint / 建立本地工作目录）
- `meta/stuck.md` —— 卡住时的元循环：换粒度重分类 → 查同类题 → 重新读题找被忽略的词 → 降级到工具暴力 → 放一会儿 / 看 hint

## 8. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 站点框架 | VitePress 1.x + Vue 3 | Markdown 驱动，天然适合字典式内容；自带全文搜索、侧边栏、深色模式、代码高亮 |
| Node | 已装 v22.15.0 / npm 10.9.2 | 无需额外安装运行环境 |
| 搜索 | VitePress 内置 local search（MiniSearch） | 离线可用，无外部服务 |
| 语言 | 简体中文，术语保留英文原文 | |
| 离线 | `npm run build` 后用 `serve.bat` 起本地静态服务 | VitePress 生成绝对路径资源，`file://` 直开不可靠，脚本更稳妥 |
| 版本控制 | git 本地仓库 | 内容迭代需要历史 |

## 9.1 已决的构建取舍（评审后补充）

以下五点是评审提出、由构建方自行拍板的事项。用户可在看到成品后推翻。

### 取舍 1：例题的"可复现"标准

- **不要求**下载并运行原题附件（很多题已下架、需要比赛环境、或依赖不可达的服务）。
- **要求**：例题分两类
  - **自建样例**：数字、命令、输出必须由实际执行验证（例如 RSA 例题的 `n/e/c` 由 Python 现场生成并验证开方成立）。
  - **公开原题引用**：写明比赛、年份、题名，解析写清判断流程走到第几条；不伪造精确 flag 字符串，标注"以原题平台为准"。
- 判定标准：**页面上出现的每一个数字和命令输出，要么跑过，要么不写。**

### 取舍 2：知识来源

- 主干：构建方自身的 CTF 知识体系。
- 校对：可达的公开源（BUUCTF、gitee 镜像、PyPI 上的工具文档等）。
- **不依赖**：github.com、raw.githubusercontent.com、ctftime.org、Docker Hub —— 实测在本机不可达。
- 不承诺"全网爬取"，承诺"体系完整 + 可校对"。

### 取舍 3：多主题题型不拆页

Web 12、Pwn 10、Crypto 10 中有几项把多个弱相关主题捆在一页（如「HTTP 层杂项」）。
**保持一页**，但把模板的 ③ 判断流程扩充为两段式：

```markdown
### ③-1 子类型分流   （先判断这是哪一种子类型）
### ③-2 该子类型内的成本排序链
```

子类型分流本身也是一条成本排序链，因此不违反"判断流程必须是优先级列表"的原则。

### 取舍 4：搜索验收

- 已启用 `Intl.Segmenter` 中文分词（见 `config.mts`）。
- 每个题型页在文首加一行 `关键词：`，用空格分隔同义词与英文名，保证分词后能被命中。
- **验收查询清单**（构建后逐条手测，任何一条无结果即不通过）：
  `注入`、`盲注`、`sqli`、`sql 注入`、`反序列化`、`伪加密`、`pcap`、`ret2libc`、`堆`、`格式化字符串`、`RSA`、`盲水印`、`volatility`、`JWT`、`SSTI`

### 取舍 5：总表粒度

- `map.md` **按可观察症状组织**（不是按题型编号 1–58）。
- 目标 60–80 行，每行一个"看到什么 → 去哪页"。
- 人工维护；每页 ① 识别指纹 是它的上游事实源，改页面时同步改总表。

## 10. 留给成品后再定的

用户明确表示页面细节等看到成品再定。以下事项不在本次确定范围：

- 页面视觉风格、配色、字体
- 导航层级是一层还是两层
- 是否给题型加"难度 / 出现频率 / 比赛权重"标签
- 每页例题是否从 1 道加到多道
- 是否需要"输出循环"可勾选的交互组件（当前按纯 Markdown 实现）
