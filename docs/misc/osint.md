# OSINT、二维码与杂项

关键词：OSINT 开源情报 图片反查 以图搜图 Google Lens Yandex TinEye 百度识图 地理定位 geolocation 阴影 路牌 车牌 EXIF GPS 社交媒体 用户名溯源 二维码 QR zbarimg 条形码 barcode 破损二维码 纠错 qrazybox

## ① 识别指纹

- 附件是一张图片、一张截图，或只有一段文字、一个用户名
- 题干问"这是在哪"、"什么时候拍的"、"这个人是谁"、"这是什么地方"
- 题干出现"拍摄地"、"经纬度"、"城市"、"人物"、"社交账号"、"原图"
- 图片里没有明显隐写特征，但有地标、店招、路牌、车牌、文字
- 附件是二维码 / 条形码，或者二维码被遮挡、破损、反色
- 题干给了 URL、用户名、邮箱、手机号、域名
- 题干很长、信息密集，分值却不高 —— 线索都在文字里
- 图片被裁剪、压缩过，EXIF 可能已经被平台剥掉

## ② 考什么

- **以图搜图**：Google Lens、Yandex、TinEye、Baidu、Bing Visual Search
- **地理定位**：文字 / 语言 / 路牌 / 车牌 / 建筑 / 植被 / 电线杆 / 道路标线
- **阴影与太阳方位**：用拍摄时间和影子方向反推朝向、纬度
- **EXIF**：GPS、拍摄时间、设备型号、软件名
- **社交媒体溯源**：用户名复用、历史快照、WHOIS / DNS、GitHub 提交邮箱
- **二维码**：版本、纠错等级、掩码、定位块，破损后的重建
- **条形码**：EAN / UPC / Code 128 的编码与校验位
- **题干阅读**：每一句话、每一个名词都是检索词
- **地图工具**：Google Maps / Street View、Mapillary、OpenStreetMap / Overpass

## ③ 判断流程

### ③-1 子类型分流

1. 附件是图片，题干问"在哪 / 拍摄地 / 坐标" → 地理定位，跳到 ③-2 第 1 条，按成本链走到第 4 条。
2. 图片里有人物、物体、logo、建筑，题干问"这是谁 / 这是什么 / 哪里" → 以图搜图，跳到 ③-2 第 1 条，按成本链走到第 3 条。
3. 附件或图片里含二维码 / 条形码 → 码解码，跳到 ③-2 第 2 条。
4. 题干给用户名、邮箱、域名、社交账号 → 社工溯源，跳到 ③-2 第 5 条。
5. 只有文字，没有附件 → 文本检索，跳到 ③-2 第 6 条。
6. 图片有多张，或题干强调"原图 / 拍摄信息" → 先读 EXIF，跳到 ③-2 第 1 条。
7. 以上都不匹配 → 跳到 ③-2 第 1 条。

### ③-2 成本排序链

1. 对所有图片跑 `file` + `exiftool`，读 GPS、DateTimeOriginal、Make / Model、Software、Comment；有 GPS → 直接换算经纬度，结束；没有 → `strings -n 6 图片 | grep -iE 'flag|ctf'`，命中 → 结束；没有 → 跳第 2 条。
2. 二维码 / 条形码：`zbarimg -q --raw 图片`；解出内容 → 按内容类型处理（URL、文本、下一层编码、flag），结束；解不出 → 放大、灰度、二值化、反色后再试，仍失败 → 跳第 3 条，同时记录二维码版本与纠错等级。
3. 以图搜图：先裁剪主体、去掉水印、旋转 90°、镜像，再分别投 Google Lens、Yandex、TinEye、百度识图；命中原始帖子、同款物体或地点 → 打开原帖 / 原图并记录来源，结束；没有结果 → 跳第 4 条。
4. 地理定位：把图中所有文字（店招、路牌、广告、车牌）逐条搜索；按车牌格式、语言、植被、建筑风格缩小到国家和城市；用影子方向和拍摄时间算太阳方位；在 Google Street View / Mapillary 找同角度街景 → 命中坐标或地标 → 结束；没有 → 跳第 5 条。
5. 社交溯源：用户名在所有平台搜索（`sherlock 用户名`），查 archive.org 历史快照、WHOIS、DNS、GitHub 提交邮箱 → 命中身份、位置或关联账号 → 结束；没有 → 跳第 6 条。
6. 重读题干：逐句拆名词，把每个专有名词、数字、日期都当搜索词；非中文题干先翻译；再看题目名、文件名、URL 路径 → 出现新线索 → 回第 1 条；没有 → 跳第 7 条。
7. 兜底：以上全不成立 → 回到第 1 条，换图重看：原图 → 裁剪图、当前搜索引擎 → 另一个引擎、图片 → 图片里的文字；把所有搜索结果截图存档逐条比对。

## ④ 工具与命令

```bash
file 图片.jpg
exiftool 图片.jpg
exiftool -GPSLatitude -GPSLongitude -GPSPosition 图片.jpg
exiftool -a -G1 -s 图片.jpg          # 所有元数据，按组显示
strings -n 6 图片.jpg | grep -iE 'flag|ctf|http'
```

```bash
# 二维码 / 条形码
zbarimg -q --raw qr.png              # -q 安静模式，--raw 只输出内容
zbarimg -q --raw barcode.png
qrencode -o out.png 'flag{...}'      # 自己生成对照图
```

```python
# pyzbar：zbarimg 不可用时的替代
from PIL import Image
from pyzbar.pyzbar import decode

print([o.data for o in decode(Image.open('qr_damaged.png'))])
```

二维码破损后的处理顺序：先用 `zbarimg` 或手机扫码直接试（纠错等级高时能直接过）；再放大、二值化、反色；仍不行就看定位块是否完整，用 `qrazybox` 之类的工具按版本、纠错等级、掩码手工重绘缺失模块。

## ⑤ 常见坑

| 现象 | 实际原因 | 正确应对 |
|---|---|---|
| `exiftool` 里 GPS 是 0,0 | 平台重编码时把坐标清零了 | 换原图 / 图床原图，或放弃 EXIF 走视觉线索 |
| 二维码怎么扫都失败 | 图片模糊、对比度低、被反色 | 放大 2–4 倍、转灰度、二值化、反色后再扫 |
| 二维码中间缺一块但还能扫 | 纠错等级高，缺的码字被恢复了 | 直接读；不要手工补，先信纠错 |
| 二维码缺的是定位块 | 定位块不参与纠错，缺了就无法定位 | 需要用工具按版本和掩码重绘，不能只靠纠错 |
| 以图搜图没有结果 | 图被裁剪、加水印、镜像或翻转 | 先裁主体、去水印、镜像后再搜，换引擎再试 |
| Google 搜不到地点 | Google 对中文小店和街景覆盖弱 | 换 Yandex、百度识图，或直接搜店招文字 |
| 车牌国家判断错 | 只看了颜色，没看格式 | 查目标国车牌格式、字符集和尺寸比例 |
| 街景和照片对不上 | 街景是几年前拍的 | 用建筑、店招、道路变化交叉验证，查历史街景 |
| 题干说"附近"却找不到精确点 | "附近"是范围线索，不是坐标 | 找参照物和交叉路口，先锁定街区再细化 |
| 截图里没有任何元数据 | 截图工具不保留 EXIF | 改用原始照片，或走纯视觉 / 文字线索 |

## ⑥ 例题

**题目**：破损二维码
**来源**：自建样例（二维码纠错是二维码题的基础；实际比赛按原题平台为准）

**题干**：给一张二维码图片，中间被一块白色方块盖住，要求读出二维码内容。

**附件**：`qr_damaged.png`，410×410 的 PNG，二维码版本 4（33×33 模块），纠错等级 H。

**关键观察**：
- `file` 显示 `PNG image data, 410 x 410`
- 二维码三个定位块完整，只有中间的数据区被白色方块覆盖
- 版本 4 的模块数是 `21 + 4 × 3 = 33`，图片边长 `(33 + 8) × 10 = 410`，说明每个模块 10 像素、静区 4 模块
- 纠错等级 H 能恢复约 30% 的码字；白块 120×120 像素，按每模块 10 像素算是 12×12 个模块，并且三个定位块完整

**走了哪条链**：③-1 第 3 条（二维码）→ ③-2 第 2 条（直接解码）。

**命令与输出**：

```text
$ file qr_damaged.png
qr_damaged.png: PNG image data, 410 x 410, 8-bit/color RGB, non-interlaced
```

```python
from PIL import Image
from pyzbar.pyzbar import decode

print([o.data for o in decode(Image.open('qr_damaged.png'))])
```

```text
[b'flag{qr_error_correction_demo}']
```

**结果**：二维码内容被直接解出；提交时按平台要求写成 `flag{...}`，具体值以原题平台为准。

**为什么盖住中间还能解**：二维码的数据区按 Reed-Solomon 码编码，H 级最多能恢复约 30% 的码字；中间白块破坏的码字没有超过这个比例，解码器用纠错补回来了。但三个定位块不参与这套纠错 —— 把左上角定位块盖住后，同一张图就无法定位，解码直接失败。所以"破损二维码"先判断缺的是数据区还是定位块，两种情况处理方式完全不同。

::: tip OSINT 的第一原则
**先把题干读完，再打开搜索引擎。** OSINT 题的线索密度极高：一个地名、一个日期、一个"附近"、一个用户名，往往就是整题的入口；跳过题干直接以图搜图，常常搜到一堆无关结果。
:::
